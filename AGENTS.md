# Repository Guide for Coding Agents

## Scope and source of truth

This repository publishes one lab manual in two formats:

- `gh_pages/` builds the Docusaurus website.
- `pdf-gen/` builds board- and OS-specific PDFs.
- `lab_manuals/markdown/` is the source of truth for written content.
- `lab_manuals/static/images/` is the source of truth for figures.

Do not edit generated content under `gh_pages/.docusaurus/`, `gh_pages/build/`, or
`lab_manuals/pdf/` by hand. PDF files are regenerated by the PDF workflow.

## Content layout

- `lab_manuals/markdown/home.md`: shared manual landing page.
- `lab_manuals/markdown/shared/`: labs or fragments shared by multiple boards.
- `lab_manuals/markdown/<board>/`: board overview and board-visible lab pages.
- `lab_manuals/markdown/appendices/`: shared appendices.
- `lab_manuals/static/images/<lab-or-board>/`: image assets, referenced as
  `/images/<lab-or-board>/<file>` from Markdown.

Docusaurus excludes `shared/`, so a shared lab must be symlinked into every applicable board
directory. The symlink path also lets the website's variable plugin infer which board is being
built. Lab 3 demonstrates another pattern: each board page defines its board-specific Purpose and
Overview, then imports a shared procedure fragment before adding its own peripheral instructions.

Files beginning with `_` are partials. They are excluded from the sidebar and should not contain
frontmatter or a page-level `#` heading.

## Authoring conventions

- Give every page YAML frontmatter with `title`, `sidebar_label`, and `sidebar_position`.
- Use one `#` heading per page, then `##` for major sections, `### Step N.M`, and
  `#### N.M.N` for numbered instructions.
- Use Docusaurus admonitions (`:::info`, `:::tip`, `:::warning`) and fenced code blocks.
- For OS-specific commands, import `Tabs` and `TabItem`, then use `linux`, `macos`, and
  `windows` tab values. Keep all three variants unless the instruction is genuinely universal.
- Use `%BOARD%`, `%BOARD_NAME%`, and `%FLASH_ARGS_*%` rather than hard-coded board commands.
- Use `/images/...` absolute site paths. Add meaningful alt text. A missing image is acceptable
  only while a task explicitly calls for a placeholder path.
- Use `{/* pdf-page-break */}` sparingly when a deliberate PDF-only page break is needed.
- Preserve Markdown/MDX syntax that works in both Docusaurus and the PDF unified pipeline.

## Add a lab

For a board-specific lab:

1. Add `lab_manuals/markdown/<board>/labN.md` with frontmatter and a unique
   `sidebar_position`.
2. Add figures under `lab_manuals/static/images/labN/` or the board image directory.
3. Add `labN.md` to `pdf-gen/config.mjs` `pages` at the intended manual position.
   A bare filename is resolved inside each board directory and skipped for boards where it does
   not exist.

For a shared lab:

1. Add `lab_manuals/markdown/shared/labN.md`.
2. Add a relative symlink in each board directory:
   `ln -s ../shared/labN.md lab_manuals/markdown/<board>/labN.md`.
3. Add the bare filename to `pdf-gen/config.mjs` `pages` once.

If only part of a lab is shared, put the partial in `shared/_name.md`, symlink it into each board
directory that imports it, and import it with a relative MDX import from the board page. Keep
board-specific Purpose and Overview text in the board page rather than the shared partial.

The website sidebar is autogenerated, so adding a page normally requires no sidebar edit.

## Remove a lab

1. Remove the page or board-directory symlinks that publish it.
2. Remove its entry from `pdf-gen/config.mjs` if no board uses that filename.
3. Remove a shared source or partial only after confirming no imports or symlinks reference it:
   use `rg '_partial-name|labN.md' lab_manuals/markdown` and `find lab_manuals/markdown -type l`.
4. Remove images only after checking that no remaining Markdown references them.
5. Renumber `sidebar_position` values only when the desired navigation order changes.

## Add a board

1. Create `lab_manuals/markdown/<board>/index.md` and any board-specific lab pages.
2. Symlink applicable shared labs and partials into the new board directory.
3. Add the board and its substitution variables to `pdf-gen/config.mjs` under
   `versions.boards`.
4. Add the same web substitution values to the `boardMap` in
   `gh_pages/plugins/remarkBoardVars.mjs`.
5. Add `<board>Sidebar` to `gh_pages/sidebars.js` and its navbar item to
   `gh_pages/docusaurus.config.js`.
6. Add board images under `lab_manuals/static/images/<board>/`.
7. Generate at least one board/OS PDF and build the website.

`pdf-gen/plugins/boardVars.mjs` is generic; PDF values come from `pdf-gen/config.mjs`. Do not add
a second hard-coded PDF board map.

## Remove a board

Reverse the board-addition steps: remove its Markdown directory, PDF config entry, website
variable entry, sidebar, navbar item, and board-only images. Before deleting shared content,
confirm another board does not use it. Generated PDFs for a retired board may be deleted when the
task explicitly includes removing that board's published artifacts.

## Validation

Run the checks relevant to the files changed:

```bash
cd gh_pages
pnpm run build
```

```bash
cd pdf-gen
node generate.mjs --board same54 --os windows
```

Replace `same54` and `windows` with the affected board and OS. For shared or pipeline changes,
test every affected board and at least one OS; test all OS variants when tabs or OS filtering
changed. Missing placeholder images may produce warnings, but MDX parse errors, unresolved
imports, unsubstituted `%TOKENS%`, and broken internal links must be fixed.

Before finishing, inspect `git status --short` and `git diff --check`. Preserve unrelated user
changes and untracked source documents.
